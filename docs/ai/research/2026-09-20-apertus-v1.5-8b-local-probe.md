# Apertus v1.5-8B on the RX 7900 XTX: loads, answers in five languages, frames tool calls, and fabricates tool outputs if not stopped

Follow-up to the [8–12B hardware plan](../plans/2026-09-19-capable-8-12b-akh-hardware-plan.md), which put
Apertus v1.5-8B into Stage 0 as an Apache-2.0 candidate next to Gemma 4. This is the first local run. It is a
smoke probe, not a capability-contract run; nothing here scores the R1 twelve families.

## The offload trap

`ollama create` from the Q8 GGUF succeeded and the first prompt answered coherently at **4.3 tok/s** — CPU speed.
`ollama ps` showed `71%/29% CPU/GPU`: Ollama's memory estimator offloaded a third of the layers to a card with
23.9 GiB free for a model needing ≈11 GB (8.6 GB weights + ≈2 GB f16 KV at 16k context). `PARAMETER num_gpu 99`
in the Modelfile forces full offload; nothing else changed. This will bite anyone serving an unfamiliar
architecture through Ollama and should be the first thing checked when a new GGUF is slow.

No speaker has graded these; "coherent and on-topic" is the only claim.

## Tool calling, proven at the token level

Visible output for the two-tool prompt (`memory_recall`, `memory_write`) looked like `…tool.[{"memory_recall":
{"entity": "Ada Lovelace"}}]{ "entity": … }Now I'll store…[{"memory_write": {…}}]…` — the template's JSON call
shape, but with no visible control tokens and no halt after the call. Ollama strips control tokens from output
and matches stop strings against the rendered text, so a `stop: ["<|tools_suffix|>"]` never fires and the
question "does the model emit the framing tokens at all" cannot be answered through Ollama's API.

Asking the underlying llama-server runner (`127.0.0.1:<port>/completion`, `return_tokens: true`, temperature 0)
answers it:

| position | token id | name |
|---:|---:|---|
| 20 | 71 | `<|tools_prefix|>` |
| 21–37 | — | `[{"memory_recall": {"entity": "Ada Lovelace"}}]` |
| 38 | 72 | `<|tools_suffix|>` |
| 39 | 73 | `<|tool_output_start|>` |
| 40… | — | a fabricated JSON "result" for Ada Lovelace, then a second call |

Cross-check through Ollama alone: `eval_count` 160 vs 153 tokens for the visible text — 7 hidden tokens for two
call lists, consistent with prefix+suffix per call plus one role-played output pair.

So:

1. **The tool-call contract is machine-parseable.** Stop at token 72 (or on text after it) and the call list
   is clean JSON in the documented `[{"name": args}]` form. This is what vLLM's `--tool-call-parser apertus`
   does; our runtime would need the same stop.
2. **Left unstopped, the model emits `<|tool_output_start|>` itself and invents the tool's answer**, then
   proceeds as if the tool had run. That is expected for any raw-completion loop, but for this project it is the
   concrete form of the captain-boundary rule (ADR 110): the harness, not the model, must own the turn after
   token 72. A runtime that streams past it will feed the model fabricated observations.

## What this does not establish

- **Nothing about the R1 capability contract.** No graph acquisition, restart recall, repair or authorization
  was exercised; the 100-world pack still does not exist.
- **No tool-calling accuracy number.** One two-tool prompt at temperature 0; the argument choice was sensible
  but no BFCL-style score exists for Apertus v1.5 anywhere, and this probe does not create one.
- **Language quality is ungraded.** Coherent to a non-native reader; the Portuguese-basics contract will decide.
- **These are community text-only trims**, exported as the v1 `apertus` architecture. Whether the trim changed
  anything beyond dropping the vision/audio vocab is not verified against the gated official weights.
- **Thinking mode (`Deliberation: enabled`, `<|inner_prefix|>…<|inner_suffix|>`) was not probed.**
- **Candle/Burn runtime support does not exist** for `apertus` (xIELU, QK-norm); this ran on Ollama's
  llama.cpp. Extending the Ptah runtime is the operator's stated brainstorming item, not a plan.

Serving state after this probe: user-mode Ollama left running on port 11435 (`pkill -f 'ollama serve'` to stop;
the model unloads itself after 30 min idle). Both GGUFs and the probe outputs stay under
`~/.local/share/ollama-apertus/`.
