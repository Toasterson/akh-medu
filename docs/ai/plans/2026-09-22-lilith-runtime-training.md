# Lilith training in the runtime

The user superseded the small-context standalone experiment: allow ordinary
Gemma reasoning to finish, and train inside `akhrtd` with the same tools available
during inference. The closed experiment and its resource measurements remain in
`training/lilith/adam-kaine-gemma-20260922/run3/`. It produced no policy update.

The pinned Gemma parent advertises 262,144 positions. That architectural limit
is distinct from the memory required by this machine's training implementation.
The next worker starts with 32,768 context positions and 16,384 generated tokens;
these are operational ceilings, not an efficiency or Neuralese experiment.
It must never discard context or label an unfinished answer a coding failure.

## Runtime boundary

`akhrtd` owns a pinned training worker process, its deadline, cancellation and
process-group cleanup. `akhsessd` supplies the authoritative session tools and
approval policy. The worker requests tools through the existing runtime `Host`
callback; it never obtains daemon credentials or substitutes direct workspace
access. Training and inference profiles use the same serialized tool catalog.
Parent weights, dataset, experiment protocol and output directory are selected
by a pinned operator-owned worker configuration, not model-generated arguments.

Transport is bounded NDJSON over the managed child's standard input/output:

- Host: `{"type":"start","request":RuntimeJobRequest,"config_path":string,"config_sha256":string}`.
- Worker: `{"type":"tool_call","id":string,"name":string,"arguments":object}`.
- Host: `{"type":"tool_result","id":string,"result":ToolResult}`.
- Worker: `{"type":"progress","phase":string}` (no raw reasoning).
- Worker: `{"type":"completed","output":string}` or
  `{"type":"error","message":string}`.

Unknown tools, duplicate call identifiers, malformed frames, hash drift and
ambiguous completion fail closed. Tool success is an actual broker receipt, not
a statement generated by the model. Cancellation never silently resumes a
possibly effective training job.

## Memory and learning

Only the final layer's query LoRA is trainable. Lower-layer states and all cached
keys/values are independent of those parameters. A cached token replay can
therefore accumulate exact query-adapter gradients without retaining an entire
reasoning graph. Every cache tensor must have no gradient function; all other
parameters must remain frozen. For target token i, the input is token i-1 with
the cache containing tokens through i-2. The optimizer steps only after the bank.

Cache construction explicitly instantiates the configured sliding and global
layers. The installed Transformers constructor treats zero shared-KV layers as
an empty `[:-0]` slice and falls back to unbounded full-attention storage.
CPU offloading uses blocking transfers on the caller stream. The installed
asynchronous prefetch implementation produced different logits on identical
replays on this ROCm machine; resident and synchronous transfers were repeatable.
The engine does not patch the installed library or change attention arithmetic.

This requires measured controls: token alignment, full-prefix versus cached
logits/loss/gradients, exact sampler replay, sliding-window crossings at
1023/1024/1025, global attention beyond that boundary, long-context memory,
adapter effect and cold reload. Generation uses the pinned thinking-enabled
Gemma template. Tool observations are context, never sampled policy actions.

Numerical qualification separates three questions: a small FP32 full-forward
reference checks the gradient identity; the actual BF16 parent compares resident
and synchronously offloaded tokenwise execution at the 1,024-position boundary;
and collection/replay must reproduce the same policy log probabilities. Batched
BF16 full-forward differences are retained separately, since its reduction
shapes differ from tokenwise execution. They must not be reported as passing the
old `1e-4` batched-equivalence gate. Tecton, using Kimi K3, endorsed separate strict determinism and precision-aware
cross-shape checks. The small FP32 regression supports the gradient identity;
it is not a universal numerical proof. BF16 cross-shape calibration remains
open, particularly for the larger boundary deviations. See
[the review disposition](../../../training/lilith/runtime-training-engine-20260922/kimi-math/README.md).

Transcript imitation, tool-grounded reward updates and same-parent adapter
interpolation remain separate arms. Development selects; paired sealed
evaluation runs only after selection is frozen. No automatic deployment or
quality claim follows a successful mechanics test.
