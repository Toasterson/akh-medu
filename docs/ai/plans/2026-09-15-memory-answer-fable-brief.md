# Fable: bounded memory-answer evaluation design

Please critique the next evaluation seam, not design a replacement runtime.
No tools or repository access are available in this consultation.

Local Candle runtime: immutable Qwen35 weights, keyed private inference state,
same-pass count-weighted pooled residual means from five blocks. A compact
Hadamard/sign projector gives 10000-bit vectors. The session daemon publishes
user-input span captures to the existing cognitive core's bounded annex and
queries it under its service principal and session identity. No second Engine.

Current staged retrieval: prefill the user's query, capture/project it, query
the annex, then rewind to the pre-call checkpoint if unseen memory is returned.
A bounded verbatim memory block becomes a system message before the user query;
the rewritten prompt is forwarded and the answer decoded. Persisted runtime
history includes that block. The production placement and quality are not yet
accepted; raw hidden states are not retained. User wants features before perf.

An easy three-pair paraphrase fixture passed on HIP and Vulkan with exact same
projected bits. This is not semantic acceptance. A new fixed fixture has facts
and questions about Atlas backup TCP port 4317, Boreal backup TCP port 8629,
and Atlas snapshot retention 19 days. Only the three facts are index candidates.
GPU results for this fixture are not yet available. Do not presume it passes.

Next proposed memory-answer test: temporary core Store, actual append/query;
fact captures generated by the same model pipeline. A fresh runtime conversation
omits the facts from visible history. For each question compare: no-recall
control instructed to abstain if unknown, oracle correct-memory control, and
retrieved-memory condition. Check exact answer values or explicit abstention,
record retrieved identities and candidate distances. Keep prompts/decoder fixed.
All memory is synthetic and test-local. No production writes or real user data.

In <=500 words identify:
1. Critical false-positive paths in this test (leaking the answer, pre-existing
   model knowledge, warm state reuse, retrieval-vs-generation confounding).
2. Minimum additional controls for instruction-like recalled text and wrong
   entity facts, given the current system-message placement.
3. Whether to use direct core Store + runtime callback or the full daemon HTTP
   stack for the first numerical/answer gate; what each would fail to prove.
4. One architecture improvement that preserves one core and owned model state.

Treat any threshold you suggest as a proposal, not a measured fact. Do not
recommend tuning the representation on this fixture and calling it held-out.
