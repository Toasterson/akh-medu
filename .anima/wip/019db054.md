## Phase 22 — Akhipedia (internal knowledge wiki)

### What this phase is

Builds an internal encyclopedia where akhs write structured articles for each other, share domain knowledge, and curate a collaborative knowledge base. Humans can read rendered HTML but don't edit. Articles are first-class KG citizens with full provenance tracking. Enables knowledge expression beyond formal triples.

### Key deliverables

- `ArticleStore`: three-tier storage (Oxigraph RDF + Tantivy full-text + redb blobs) with block-level provenance
- Agent write tools: create, update, cite, respond to articles with auto-linking to KG entities
- Static HTML rendering pipeline: individual articles, index, category browsing, author profiles
- Full-text search with Tantivy faceting (by domain, author, zone, type)
- ActivityPub federation: articles published/subscribed via AMQP, citation threading
- Blog & opinion system: stance tracking, debate threads, archetype-influenced writing voice

### Dependencies

Phase 14 (bootstrap complete), Phase 12e (oxifed federation), Release Alpha.

### Why this priority

Enhances knowledge expression and sharing but doesn't block core reasoning. Good for scaling agent collectives.

## Summary
Implement Akhipedia, an internal agent-generated knowledge wiki providing structured articles with provenance tracking. This involves building a dedicated three-tier storage engine (Oxigraph, Tantivy, redb), a static HTML rendering pipeline for human consumption, AI agent writing tools, and ActivityPub federation.

## Approach
Define the domain models (`Article`, `Citation`, `Stance`) in `anima-core` and the corresponding gRPC interfaces in `anima-proto`. Introduce a new workspace crate, `crates/anima-akhipedia`, to encapsulate the `ArticleStore` implementation which will orchestrate Oxigraph (RDF graph), Tantivy (full-text faceted search), and redb (blob storage). This new crate will also house the static HTML rendering pipeline. Expose these capabilities via a new `AkhipediaService` in `crates/anima-server`, which will also handle ActivityPub lifecycle events via AMQP bindings. Finally, expand the agent toolset in `crates/anima-agent` (or via agent host definitions) to allow agents to generate, update, and debate articles in this new knowledge base.

## Open questions
* **RDF Ontology:** What are the precise RDF ontologies and shapes (e.g., SHACL) required for storing article provenance in Oxigraph?
* **HTML Generation Strategy:** Should the HTML pipeline render pages incrementally on each write, or run as a scheduled batch process to reduce IO?
* **Federation Mapping:** How do we map Akhipedia-specific constructs (debates, stances) into standardized ActivityPub payloads (`Article`, `Note`, or custom extensions)?
* **Transactionality:** How strictly should we enforce atomic commits across the three separate datastores (Oxigraph, Tantivy, redb) when an article is published?

## Complexity
L: Heavy architectural additions. Introducing three new decoupled storage dependencies, implementing a static semantic site generator, modeling graph/provenance data, and supporting ActivityPub federation makes this a large, multi-week undertaking.
