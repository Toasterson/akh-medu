### What this phase is

Builds formal reasoning about what different agents know, believe, and don't know. Gives akh-medu the ability to model other agents' mental states (theory of mind) and use this to plan communicative actions strategically. Foundational for any multi-agent interaction.

### Key deliverables

- `EpistemicStateManager`: formal representation of what agents know/believe about propositions via accessibility relations
- Dynamic epistemic logic operations: public announcements, private messages, observations, questions, retractions with full update semantics
- `ToMEngine`: recursive belief modeling (Level 0–3) that predicts other agents' behavior and detects information asymmetries
- E-graph rewrite rules for epistemic inference (K-axiom, introspection, public announcement)
- ToM-based communication strategy: what to share, withhold, ask given goals and opponent models

### Dependencies

Phase 17 (evidence intervals), Phase 18 (source reliability), Phase 12d (interlocutor microtheories).

### Why this priority

Required for higher-level social intelligence (Phase 21) and communicative competence (Phase 34) — many things downstream depend on this.

## Summary
Implement Theory of Mind (ToM) and dynamic epistemic logic capabilities to enable agents to reason about other agents' knowledge and beliefs. This involves building out an epistemic state manager, a recursive ToM engine for opponent modeling, and E-graph rewrite rules to infer mental states for strategic communication.

## Approach
Because this represents a major expansion of AI cognitive capabilities, the implementation will live inside the `anima-ai` crate (as an `epistemic` module). First, the `EpistemicStateManager` will be built to represent propositional knowledge and belief accessibility relations between agents. Next, a dynamic logic update system will provide operations like public announcements, private messages, and observations that modify the graph of beliefs. The `ToMEngine` component will then wrap these states to evaluate recursive mental models (Levels 0–3) to detect information asymmetry. At the core, an E-graph inference system (likely integrating a graph-rewriting crate like `egg`) will apply epistemic axioms (e.g., K-axiom, introspection) to propagate new beliefs. Finally, a strategic communication planner will use the `ToMEngine` to assess whether to share, withhold, or query information based on goals.

## Open questions
* **Persistence:** Do these epistemic accessibility relations need to be persisted to `anima-db` between sessions, and if so, how should recursive belief structures be represented in Postgres?
* **E-graph Backend:** Should we use the Rust `egg` crate for E-graph rewrite rules, and how will it integrate with existing Phase 17/18 schemas (evidence intervals and source reliability)?
* **Performance:** How will we bound the combinatorial explosion of E-graph rewrites at Level 3 ToM (e.g., iteration limits or heuristic pruning)?
* **Crate Boundaries:** Given the complexity of epistemic logic, should this eventually be factored out into an `anima-logic` crate instead of crowding the Gemini-focused `anima-ai` crate?
