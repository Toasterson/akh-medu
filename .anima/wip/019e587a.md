## Description

tecton workspace has 56,535 provenance records for only 3,113 triples — an 18:1 ratio. Analysis of Tecton provenance shows ~120/188 records are identical `is-a-transitive` rule inferences with same antecedents (SymbolId(412), SymbolId(465)) at different timestamps. The inference engine is re-running the same transitive closure on every agent cycle without dedup. Each run creates new provenance records. This is a DB bloat catastrophe: every cycle adds ~8 duplicate is-a-transitive records per symbol touched. Fix: add dedup before provenance insert — if the same (subject, predicate, object, confidence) triple already exists, skip creating a new provenance record. Also investigate why is-a-transitive fires repeatedly for the same closure.

## Summary
The system is generating an excessive number of duplicate provenance records due to the inference engine repeatedly processing the `is-a-transitive` rule on every agent cycle. We need to deduplicate provenance insertions at the database level and correct the inference loop to stop redundant rule evaluations.

## Approach
Introduce a new database migration to add a unique constraint on the provenance table covering `(subject, predicate, object)` or `(subject, predicate, object, confidence)`. Update the corresponding insertion query in `anima-db` to use `INSERT ... ON CONFLICT DO NOTHING`, discarding duplicate inferences before they generate new timestamps and bloat the database. Afterwards, trace the agent inference loop (likely within `anima-agent` or `anima-exec`) to debug the `is-a-transitive` rule execution. Implement a diffing mechanism or state-tracking to prevent the engine from re-calculating the same transitive closure if the antecedent triples are unchanged.

## Open questions
* Should the unique constraint cover confidence, or rule out identical `(subject, predicate, object)` triples regardless of confidence/timestamp?
* Does the transitive closure re-evaluation happen inside the `anima-agent` daemon, the `anima-exec` binary, or is it triggered remotely via `anima-server`?
* Can we cache the bounds of the previous cycle's transitive closure in memory, or do we need to load existing DB triples as a baseline for the inference engine on every run?
