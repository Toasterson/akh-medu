## Description

The cluster is described in text ('11 nodes', 'cluster nodes headnode stor01 stor02...', 'Kubernetes cluster managed by Talos Linux and GitOps via Flux') but K8sNode entity type (id=450) is unused. Individual nodes (stor01, stor02, stor03, wk01-wk04, wktiny01, wktiny02, wktinystor01, headnode) appear only in concatenated string labels. IP addresses exist as bare strings (100.98.169.36, 83.77.127.23, 192.168.1.12) without IP relation linking them to hosts. Services (anima, seshat, sia, solstice, forgejo, akhomed) are known but not related to their hosts. Network topology (switches, Envoy Gateway) is described but not structured.

## Summary
The cluster's topological data (the 11 known nodes, IP addresses, and services) is currently stored as unstructured text strings instead of utilizing the designated `K8sNode` entity model. This work item will map and extract these flat text definitions into properly linked relationships in the database to establish a strictly typed network ontology.

## Approach
Update the protobuf schema in `anima-proto` to define messages for `K8sNode`, `IPAddress`, and `Service` along with their relational links. Map these definitions to new domain models in `anima-core`. Create a specific SQL migration in `anima-db` that seeds the 11 known nodes (stor01-03, wk01-04, wktiny01-02, wktinystor01, headnode) into the database using the target entity type (id=450), and links them to their associated bare IP addresses and services. Implement corresponding data access methods in `anima-db` and expose this structured topology read/write capability via `anima-server` gRPC endpoints.
