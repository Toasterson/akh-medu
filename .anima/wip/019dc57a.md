## Description

## Why this exists

The `continuous_learning` idle task in `src/agent/idle.rs` ran every 2h, took curiosity targets from the KG, fanned them out via `bootstrap/expand.rs` (Wikipedia categories + Wikidata SPARQL + ConceptNet relations), and asserted the merged result. In practice, the merge produced too much low-quality / contradictory / duplicate noise — every cycle made the KG worse, not better. As of today it's deactivated by removing it from the `IdleScheduler::tick` overdue array (the match arm and timing fields are kept so re-enabling is a one-line diff).

Don't re-enable the old path. Build a replacement that runs background ingestion through Seshat's already-deployed pipeline.

## Proposed shape

Pipeline:

```
curiosity_target (concept, gap)
  └── seshat_search    → relevant existing chunks (if any)
       └── seshat_wish → microtheory (RAG over corpus, optional LLM synthesis)
            └── triple_extractor → candidate triples with provenance
                 └── ElicitValidator (Phase 32 idea) → arity, contradiction,
                       neural-coherence, self-consistency
                      └── confidence-gated assertion to KG
```

Key differences from the old path:

- **Source-of-truth is the curated corpus**, not the open web. Garbage at ingest time becomes garbage at synthesis time, but the boundary is now in Seshat, where it can be policed (per-source reliability, deduplication, contradiction detection at ingest).
- **Two-pass synthesis**: search retrieves chunks, then synthesis produces structured triples — the `seshat_wish` tool is already designed for this and currently returns "synthesis_not_yet_implemented" (see `crates/seshat/src/mcp/mod.rs` line ~207). Wiring synthesis is part of this work.
- **No raw-API ingest in the loop**. Wikipedia/Wikidata/ConceptNet still play a role, but as bulk corpus *imports* into Seshat (one-shot, vetted, versioned), not a live fetch on every curiosity tick.
- **Provenance everywhere**: every assertion records (curiosity target, retrieved chunks, synthesis confidence, validator scores). Bulk retraction becomes possible if a synthesis turns out wrong.

## Tie-in to existing phases

- **Phase 32 (LLM Knowledge Extraction)** describes the validator (`ElicitValidator`), self-consistency scoring, and confidence decay — that work plugs in here as the synthesis step.
- **Phase 33 (Grounded Verbalization)** isn't a prerequisite (we're going text→triples, not triples→text), but the T5 NLU model that ships with Phase 33 is the natural backend for the triple extractor.
- **Phase 26 (LLM-VSA neural bridge)** lets the validator do hallucination detection by checking whether synthesised triples have neural support.

## Summary
Implement a new background pipeline replacing raw Wikipedia/Wikidata open-web ingestion with a curated, Seshat-mediated Retrieval-Augmented Generation (RAG) approach to ensure high-quality, provenance-backed knowledge graph (KG) assertions. The new background task will search a vetted corpus, synthesize microtheories, extract structured triples, and pass them through a validator to prevent contradictory or noisy data from entering the KG.

## Approach
Replace the older idle task logic with a new `seshat_curiosity` background task in the agent's scheduler, which triggers based on detected KG knowledge gaps. Within the AI integration crate, build out the previously stubbed `seshat_wish` tool to execute RAG over the vetted corpus. Feed the resulting text synthesis into a newly constructed `triple_extractor` to yield candidate assertions, each tagged with comprehensive provenance (search chunks, target gap). Finally, route these candidates through a new `ElicitValidator` (implementing v1 arity, structural, and dedup checks) to confidence-gate assertions before persisting them, and introduce a `kg_health_check` to continuously evaluate the ingestion metrics.
