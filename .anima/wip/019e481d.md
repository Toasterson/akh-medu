## Description

Run forward-chaining inference and return what WOULD be derived, without asserting any triples to the knowledge graph.

Parameters:
```
{workspace, max_iterations:5, min_confidence:0.5}
```

Response:
```json
{
  "total_derived": 142,
  "iterations": 3,
  "fixpoint_reached": false,
  "by_predicate": {
    "part-of": 89,
    "is-a": 23,
    "similar-to": 30
  },
  "top_triples": [
    {"subject":"Tecton","predicate":"is-a","object":"Storage nodes","confidence":0.95,"chain_length":4},
    ...
  ],
  "top_entities": {
    "most_derived_for": ["Tecton", "MacMini", "akh-medu"],
    "chain_sources": ["episode:848", "episode:797", "criteria:find_star"]
  }
}
```

Why critical: We spent 2026-05-20 fighting infer_rules contamination blind. We had no way to see what inference WOULD do. Combined with the noise entity filter (f1e39fd), this closes the audit gap completely — preview, verify, then run with confidence.

## Summary
Implement an `infer_preview` Model Context Protocol (MCP) tool that simulates forward-chaining rules without persisting data to the knowledge graph. It returns a dry-run summary containing expected metrics, derived triples, and top entities to allow auditing of inference rules before execution.

## Approach
Refactor the existing forward-chaining `infer_rules` logic to separate derivation from persistence. Introduce an in-memory overlay or a database transaction with a rollback to accumulate derived triples over the specified `max_iterations`, applying the `min_confidence` filter. Track chain lengths and sources natively during the inference loop. Once the iterations complete (or loop reaches a fixpoint), aggregate the projected derivations into the requested JSON schema (calculating counts by predicate, `most_derived_for` targets, etc.) and return the model directly without applying the `anima-db` insert operations. Define the request/response payloads in a new or existing Protobuf definition so it can be served via gRPC to the MCP provider.

## Open questions
* **State Management:** Does the current `infer_rules` logic run in-memory (making a dry run trivial) or relies heavily on recursive SQL (requiring a transaction rollback approach)?
* **Chain Tracking:** Does the existing rule engine already track `chain_length` and `chain_sources`, or do we need to instrument the inference derivations to keep track of audit metadata?
* **Transaction Size limits:** If we use a rollback strategy, are there any pg_transaction size concerns when running inference over `workspace` with high max iterations?
* **API Exposure:** Since this is specified as an MCP tool, which service/process acts as the MCP server? Is it served directly out of `anima-server` via a standard API, or does `anima-ai` wrap this?
