## Description

Ptah has 113 child-of edges, almost all to garbage: episode IDs, tool names (tool:similarity_search, tool:library_search, tool:memory_recall), literal strings (rate:0.8000, priority:69, status:dormant), and file paths (SOUL.md, memory/, MEMORY.md). Also bizarre: Ptah is-a CI runner and is-a ForgejoActions. The agents internal scaffolding (episodes, goals, tool results, file paths) is being ingested as domain facts. The identity cleaning goal (priority 200) is Active but not making progress. The inference engine must not create relations between domain entities and agent-internal scaffolding entities.

## Summary
The agent's inference engine is incorrectly extracting its internal execution context (tool names, file paths, internal parameters) as domain knowledge facts. The fix introduces programmatic filtering rules to reject scaffolding entities during fact ingestion and updates the agent's system prompt to explicitly exclude internal state from the domain graph.

## Approach
Modify the fact extraction and ingestion pipeline (likely in `anima-exec` or `anima-ai`) to include strict validation of entity names before they are persisted. Implement programmatic rules (e.g., regex constraints and prefix blocklists) that drop facts containing internal scaffolding markers such as `tool:`, `rate:`, `priority:`, `status:`, or file paths like `*.md`. Update the underlying LLM system prompt used for relation extraction to specifically instruct the model that internal agent components, files, and CI runner details are out of bounds and must not be treated as domain entities. Finally, correct the identity cleaning loop so it successfully detects and removes the existing contaminated edges, or provide a one-off automated cleanup/migration if the graph is centrally hosted.
