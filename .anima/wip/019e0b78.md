## Description

agent_goals shows 21 Active goals, but most are sentence fragments of 2-3 real goals split across IDs. The goal persistence layer should store multi-sentence goals as a single entity, not one symbol per sentence.

## Summary
Fix goal ingestion to retain multi-sentence goals as unified entities rather than splitting them into sentence fragments. Adjust the parsing logic or LLM prompts so cohesive goals are stored under a single database ID.

## Approach
Trace the goal creation pipeline from generation to persistence. First, check `crates/anima-ai` for any LLM prompts or parsing routines that might instruct the model to produce single-sentence structures or that deserialize list items improperly. Next, inspect the ingestion logic in `crates/anima-server/src/services/agent.rs` or `crates/anima-agent` for aggressive deterministic string splitting (e.g., `.split('.')`). Remove sentence-level boundary splits and replace them with bullet point or double-newline delimiters. Ensure that tests covering goal extraction and DB insertion account for entities containing multiple sentences.

## Files likely to change
* `crates/anima-server/src/services/agent.rs`
* `crates/anima-ai/src/` (guess: prompt definition and extraction parsing)
* `crates/anima-agent/src/` (guess: agent-side goal ingestion logic)

## Open questions
* Is the fragmentation caused by deterministic text splitting (e.g., `text.split('.')`) in Rust, or by the LLM prompt returning goals in disjointed structures?
* Are we required to provide a database migration script to merge and clean up the existing fragmented goals on active agents, or do we only apply the fix to newly created goals?
* What is the new acceptable delimiter for separating truly distinct goals in an ingested text block (e.g., bullet points or newlines)?
