## Description

Akhomed runs on Mac mini (localhost:8200) — it cannot be scraped by Prometheus in the K8s cluster. The correct approach is OTLP (OpenTelemetry Protocol) push from the process to an OpenTelemetry Collector, which then routes to Mimir/Loki/Tempo.

## Scope

1. Add OpenTelemetry SDK to akhomed (Rust: opentelemetry + opentelemetry-otlp crates)
2. Instrument MCP tool calls as OTel spans (request/response, timing, errors)
3. Export metrics via OTLP: symbol count, triple count, provenance count, workspace count, query latency histogram, error rate
4. Push structured tracing logs via OTLP alongside spans
5. Configure OTLP_EXPORTER_OTLP_ENDPOINT env var to point at cluster collector

## Architecture

Mac mini (akhomed) --OTLP/gRPC--> OTel Collector (cluster) --> Mimir (metrics) + Loki (logs) + Tempo (traces)

## Dashboard

Create 'Akh-Medu' dashboard in Grafana: symbol/triple growth, query latency p50/p95/p99, error rate, workspace count, provenance record rate.

## Summary
Integrate the OpenTelemetry SDK into the `akhomed` process to export traces, metrics, and structured logs via OTLP to a central cluster collector. Additionally, create a new Grafana dashboard to visualize application-specific metrics like latency percentiles, error rates, and counts for symbols, triples, and workspaces.

## Approach
Add the `opentelemetry`, `opentelemetry-otlp`, and `tracing-opentelemetry` crates to the target application's dependencies. Reconfigure the application's telemetry bootstrap in `main.rs` (or a dedicated `telemetry.rs` module) to initialize an OTLP gRPC exporter matching the `OTLP_EXPORTER_OTLP_ENDPOINT` environment variable, connecting it to a global `MeterProvider`, `TracerProvider`, and a `tracing` log subscriber.
