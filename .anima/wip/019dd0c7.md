## Summary
Introduce a new `heka-bridge` daemon to proxy OpenAI-compatible tool calls to local MCP actions and serve a text-clipping browser bookmarklet. This ensures any external AI assistant (ChatGPT, Cursor, Aider, etc.) can integrate with the platform's memory system without requiring native MCP support.

## Approach
Initialize a new workspace crate `crates/heka` and register it in the root `Cargo.toml`. Set up a lightweight HTTP server in `crates/heka/src/bin/heka_bridge.rs` (e.g., using Axum) configured to bind to port 7000. In `src/bridge/openai.rs`, implement a `/v1/chat/completions` proxy endpoint that intercepts OpenAI tool-calling requests, maps them to local Heka MCP commands like `heka_recall` and memory operations, and formats the results back into OpenAI's JSON structure. In `src/bridge/browser.rs`, expose a `/bookmarklet` endpoint returning a minimal JS clipper, plus a POST route that invokes `heka_remember` with `tool=browser` for clipped text. Finally, create markdown files in `crates/heka/hooks/` to document base URL and prompt configurations for Windsurf, Cline, Aider, and Codex.

## Open questions
* **Authentication:** How should authentication be handled for external callers (e.g., ChatGPT Custom GPTs on the public internet) hitting the OpenAI endpoints?
* **CORS Policy:** Because the bookmarklet fires cross-domain POST requests to `heka.local:7000`, what specific CORS headers and restrictions must the daemon impose?
* **Local Invocation:** Should the bridge shell out to a local MCP binary/script, or does it communicate with `anima-server` via gRPC to execute the memory operations?
* **LLM Passthrough:** For standard chat messages without tool calls, does the bridge forward the payload to an active LLM provider (like OpenRouter via `anima-ai`), or is it strictly a mock endpoint only intended for tool execution?

## Complexity
M: 1-3 days. Standing up the web server and bookmarklet routes is straightforward, but accurately translating bidirectional payloads between the OpenAI Chat Completions tool-calling schema and the internal MCP actions requires precise mapping and manual validation against multiple editor clients.
