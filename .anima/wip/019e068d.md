## Description

When `create_workspace --role Architect` runs (today: tecton workspace), the workspace is bootstrapped with only the relation skeleton — `status` reports "Symbols: 3, Triples: 1" while `export_symbols` shows 120 schema records. Five seed packs exist (`architecture`, `common-sense`, `computing`, `identity`, `ontology`) but none are applied automatically.

For `role=Architect`, the natural starter set is `architecture` + `identity` + `ontology`:
- architecture (71 triples) — gives the workspace an architectural ontology to reason in
- identity (20 triples) — schema for self-modeling
- ontology (30 triples) — category hierarchies and core relations

Proposal:
1. Add a `--seed` flag to `create_workspace` (accepts `none` or comma-separated pack names; default per role).
2. Per-role default mapping in code (Architect → architecture+identity+ontology; Investigator → ontology+computing; Executor → ontology only; etc.).
3. Surface a hint after creation: "tip: run `apply_seed identity tecton` to populate the workspace".

Secondary UX wart from this exploration: `status` reports a wildly different symbol count than `export_symbols` (3 vs 120). The status command appears to be counting only user-asserted entities while export shows the full symbol table. Worth aligning the two readings, or labeling them clearly ("user symbols: 3 / total: 120").

Why medium: not blocking, but every role-typed workspace currently starts as a near-empty room. New homes should come furnished.

## Summary
Add a `--seed` configuration to the workspace creation flow to automatically apply foundational ontology packs based on role defaults, and resolve discrepancies in the `status` command by clearly differentiating between user and total symbol counts.

## Approach
Extend the workspace creation gRPC definitions in `anima-proto` to accept an optional `seeds` parameter. In `anima-core/src/domain/agent.rs`, map each role to its default seed packs (e.g., Architect → architecture, identity, ontology). Update the workspace initialization logic in `anima-server/src/services/agent.rs` to process the seeds argument (falling back to role defaults), inject the necessary seed records, and include the suggested "tip" string in the response. Finally, update the `status` and `export_symbols` read logic—likely spanning `anima-db/src/repo/agent.rs` for the queries and `anima-exec/src/main.rs` for formatting—to report both "user symbols" and "total" exactly as proposed.

## Open questions
* Are seed packs stored natively in Postgres (`anima-db`), baked into the `anima-exec` container image, or fetched externally? This dictates where the injection happens.
* If a user passes an invalid seed pack name, should the creation process fail and block, or proceed with a warning?
* Do we need to expose the `--seed` selection in the Slint UI (`anima-desktop`) immediately, or is this explicitly a CLI/runner-only requirement for `anima-exec` initially?
