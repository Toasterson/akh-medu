## Description

Scheduled job that turns verbatim drawers into draft Akhipedia article blocks. The thing MemPalace fundamentally cannot do.

Deliverables:
- `crates/heka/src/extract/{mod,article_propose}.rs`
- akh-medu `src/wiki/extract_from_drawers.rs` (new)
- Background scheduler hook (uses akh-medu's existing scheduler).

Flow:
1. Nightly cron scans drawers ingested since last run (per Akh).
2. Cluster drawers by shared topic_ids + high pairwise VSA similarity (greedy clustering).
3. Per cluster, generate draft Akhipedia article block (Phase 22a `wiki:has-block` types: Definition, Claim, Opinion, Prose). Use Phase 32 LLM Knowledge Extraction model when available, fall back to rule-based extraction (`src/library/extract.rs` patterns).
4. Drafts queue into Akhipedia "review" state. Phase 22 promotion flow promotes them to live articles after user/Akh review.

This is the differentiator MemPalace cannot do: verbatim → curated knowledge, automatic.

Acceptance:
- After 100 drawers across 5 sessions, ≥3 draft article blocks produced.
- Drafts queryable via existing Akhipedia search.
- Akh's "what do I know about X?" SPARQL query returns drawer-derived blocks.
- Drafts cite their source drawer IDs (provenance preserved).

Reuses: src/wiki/store.rs (Phase 22a), src/library/extract.rs, Phase 32 (when available).

Estimated lines: ~500
Dependencies: 42c, Phase 22a

## Summary
A nightly scheduled job that groups newly ingested data ("drawers") by topic and vector similarity to automatically extract curated knowledge drafts. These generated draft article blocks are saved in a review state, preserving strict provenance to their source drawers. 

## Approach
Add a new background job command to `anima-triage` to serve as the nightly scheduler hook. This job will query `anima-db` for unprocessed drawers, passing them to a new clustering module in `anima-ai` that groups them using shared topic IDs and vector similarity (VSA). For each cluster, `anima-ai` will invoke the LLM extraction model (via Gemini/OpenRouter) or a rule-based fallback to produce draft article blocks (Definition, Claim, Opinion, Prose). We will extend domain structures in `anima-core` and add a new database migration in `anima-db` to store these generated drafts in a "review" status, explicitly citing the source drawer IDs so they can be surfaced by the existing Akhipedia search and promotion flow.

## Open questions

* What is the threshold or exact metric for "high pairwise VSA similarity" during the greedy clustering phase?
* Should the rule-based fallback proceed on entirely empty/failed LLM responses, or should it pre-emptively run as a pipeline alongside the LLM calls?
