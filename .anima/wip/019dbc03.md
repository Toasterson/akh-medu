## Description

## Context

Seshat (seshd) and eventually akhomed pull neural-net weight files (ONNX sentence embeddings, NER, LLM GGUF, Candle checkpoints) at runtime. The current chart gives each workload a ReadWriteOnce PVC (`seshd-models` 2 GB, `akhomed-models` 5 GB) that has to be manually populated the first time — `resolve_model_dir()` in `crates/seshat/src/embedder.rs` still has a `TODO: auto-download from HuggingFace` and just returns an error when the files are missing.

Today we bootstrapped seshd by `kubectl cp`-ing `model.onnx` and `tokenizer.json` into the pod's PVC. That works but is not reproducible: every fresh deploy (or PVC reset, which happens on a real `helm uninstall`) needs someone with kubectl to hand-copy the files back. RWO PVC contention also made rolling updates flaky today — the new pod couldn't mount until the old one was manually deleted.

## Proposal

Use the Forgejo OCI registry we already run at `code.aopc.cloud/toasterson` to ship model weights as versioned OCI artifacts (ORAS). The hunt order should be:

1. **OCI artifact** — `oci://code.aopc.cloud/toasterson/model-<name>:<version>` (e.g. `model-all-minilm-l6-v2:0.1`). Pulled at pod startup via an init container (`oras pull ...`) into an `emptyDir` volume at `/models`. Auth reuses the image-pull credentials Flux already has.
2. **PVC fallback** — only if the chart is deployed somewhere without an OCI registry reachable (air-gapped, dev laptops running minikube). Keep the existing PVC plumbing as an opt-in (`models.source: pvc` vs. `models.source: oci`).
3. **HuggingFace direct** — last-resort fallback for local dev; never used in production.

## What this unblocks

- No more `kubectl cp` dance on fresh installs — deploy is fully declarative.
- seshd becomes stateless; the pod can move between nodes without RWO contention.
- Model versioning lives in the registry (`:v1`, `:v2-experimental`), not in the chart values — easier upgrades/rollbacks.
- Same pattern will cover akhomed's NLU + Candle models once Phase 35/36 land.

## Summary
Transition Seshat and Akhomed workloads from using manually populated Persistent Volume Claims (PVCs) for model storage to declarative, initContainer-based OCI artifact pulls from the Forgejo registry. This eliminates PVC read-write contention, makes deployments fully reproducible, and allows models to be formally versioned alongside the Helm chart.

## Approach
Update the Helm charts for `akh-medu` to optionally inject an initContainer that runs `oras pull` to fetch model artifacts directly into a shared `emptyDir` mounted at `/models`, gated by a new value `models.source: oci`. In the Rust code, update the `resolve_model_dir` function in the embedder logic to expect weights locally at this path and return a clear error if the directory is missing or empty, retiring the HuggingFace auto-download placeholder. Ensure values logic handles authentication for the init container using existing pull secrets and document the PVC fallback path for air-gapped or local environments.
