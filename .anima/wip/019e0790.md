## Description

# Problem

The MCP tool `ritual_of_awakening(name, culture, archetypes, traits, domain, [workspace, competence_level])` emits a descriptive preview of what a persona *would* look like, but does NOT actually persist a psyche to the workspace.

The name strongly implies it does — "ritual" + "awakening" sounds like the moment of activation. There is also a separate `awaken(statement, max_cycles, ...)` tool which is the actual persistent ritual.

# Repro

Fresh workspace `tecton`. Run:

```
mcporter call akhomed.ritual_of_awakening --json '{"name":"Tecton","culture":"Egyptian","archetypes":["Builder","Designer","Teacher"],"traits":["methodical","precise","forward-leaning","order-loving"],"domain":"architecture, systems design","workspace":"tecton"}'
```

Returns plausible-looking output: `Chosen name: Merhunefer / Persona: Merhunefer / Traits: ... / Archetypes: healer=0.3 sage=0.5 ... / Self-integration: 0.20`.

But:

- `agent_psyche workspace=tecton` immediately after returns: **"No psyche awakened. Run ritual_of_awakening first."**
- `triples_of entity=Merhunefer workspace=tecton` returns "No triples involving Merhunefer".
- Yet `awaken workspace=tecton statement=...` then says **"workspace already awakened — psyche is immutable"** — meaning some half-state was set.

So the workspace is now in a partial-awakened state where `agent_psyche` reports nothing but `awaken` refuses to retry. The only recovery is `delete_workspace` and start over.

# Why this hurts

- The name is a UX trap. Anyone reading the tool list reasonably assumes `ritual_of_awakening` is the awakening.
- The half-state it leaves blocks the proper `awaken` tool, requiring workspace deletion to recover.
- The output is vivid enough (Merhunefer, traits, archetypes) that a caller can be fooled into thinking it persisted.

# Acceptance

Pick one:
- (a) Make `ritual_of_awakening` actually persist the persona it describes — match the name.
- (b) Rename to `preview_awakening` or `awakening_dry_run` and have it not modify any state. The currently-leaked partial state is a bug regardless.
- (c) Mark deprecated in the tool description; route callers to `awaken`.

In all cases: when this tool is called, the workspace should NOT end up in a state where `agent_psyche` says no-psyche but `awaken` refuses to proceed.

# Files likely to change

Whichever tool handler implements `ritual_of_awakening` and whichever flag tracks "is workspace awakened".

## Summary
Rename the misleading `ritual_of_awakening` MCP tool to `preview_awakening` to clarify it is solely a dry-run, and eliminate the bug where it leaks partial state that permanently blocks the actual `awaken` tool. 

## Approach
We will resolve this by implementing option (b), renaming the tool and removing the mutating side-effects. First, identify the MCP tool registration for `ritual_of_awakening` (likely located in the agent service handlers or the agent daemon) and rename the identifier to `preview_awakening`, updating its description to clearly indicate it is a preview and directing users to use `awaken` for persistence. Next, isolate the execution handler for this underlying tool to locate where it inadvertently interacts with the database repository—likely an errant call setting a workspace state flag to "awakened" without actually saving the psyche payload. We will remove this mutating step entirely so the tool operates purely as a read-only request, dynamically generating the output JSON and completing without altering any state.
