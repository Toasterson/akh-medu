## Description

# Problem

`run_agent(goals: string, ...)` shatters its `goals` input on commas, producing one separate Goal record per comma-separated fragment.

# Repro (2026-05-08, akhomed v0.6.0)

Calling:

```
mcporter call akhomed.run_agent --json '{"workspace":"tecton","goals":"Maintain anima cron pipeline (merge-loop, promote-loop, push-diffs, open-prs, check-prs, auto-close-landed). Surface decisions for Toasty.","max_cycles":2}'
```

Resulted in **19 separate goal records** including:
- "Maintain anima cron pipeline (merge-loop"
- "promote-loop"
- "push-diffs"
- "open-prs"
- "check-prs"
- "auto-close-landed)"
- "Surface decisions for Toasty"

Each fragment was assigned `priority=128`, `criteria="Agent-determined completion"`. The agent then attempts to "complete" each fragment as a separate goal — wasted OODA cycles and confused state.

# Why this hurts

`run_agent` is the documented way to set goals. Any natural-language goal that mentions a list, a tuple, or a parenthetical with commas — which is most real-world goal phrasing — gets corrupted. Operators have to discover the workaround (use slashes, or one-sentence-per-line, NEVER inline commas) by accident.

# Acceptance

- `run_agent(goals="Manage A, B, C and D.")` produces **one** goal record, not four.
- The goal parser splits on a more semantically-meaningful boundary (paragraph break, blank line, explicit numbered/bulleted list markers) — or accepts a structured `goals: string[]` parameter alongside the free-text form.
- Existing tests cover the comma case.

# Files likely to change

Source of `parse_goals` / wherever `run_agent` decomposes its `goals` input. Probably `src/agent/goals.rs` or similar.

# Workaround until fixed

Use slash-separated lists ("merge-loop / promote-loop / push-diffs"), explicit one-sentence-per-line, or semicolons. Never inline commas in lists.

## Summary
Modify the `run_agent` endpoint to accept a structured list of goals and update the legacy text parser to split on newlines instead of commas. This prevents natural language comma usage from erroneously fragmenting agent goals.

## Approach
Add a `repeated string structured_goals` field to the `RunAgentRequest` message in the agent protobuf definition. In the server's agent handler, check for `structured_goals`; if populated, use it directly. For the legacy string `goals` parameter, update the parsing logic in the core domain to split on newlines (`\n`) and semicolons (`;`) rather than commas. Trim whitespace and empty strings from the resulting fragments, and explicitly add unit tests in the domain crate to ensure commas and parentheticals remain safely inside single goal records.

## Files likely to change
* `proto/anima/v1/agent.proto`
* `crates/anima-server/src/services/agent.rs`
* `crates/anima-core/src/domain/agent.rs`

## Open questions
* Should the legacy parser proactively strip markdown list markers (like `- `, `* `, `1. `) after splitting by newline?
* Are there any internal scripts relying on the comma-splitting behavior that we need to migrate to the new `structured_goals` array?

## Complexity
S: <1 day, as modifying a string split delimiter, adding a non-breaking protobuf field, and adding basic string-parsing unit tests is a highly localized and straightforward task.
