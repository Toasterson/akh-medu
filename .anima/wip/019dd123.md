## Description

## Summary

Implement Pattern B of the four LLM-call patterns inside the Phase 41 ThinkingLoop: consume thinking-trace-emitting APIs (primarily OpenRouter as a multiplexer to Anthropic / OpenAI / DeepSeek / Gemini extended-thinking endpoints), re-encode each thinking-block chunk through the bridge as a synthesised `ThoughtStep`, and fold the result into the loop's hypothesis superposition.

Pattern B's role is two-fold:
- **Information import** — pull frontier-model reasoning into akh-medu's symbolic state for downstream verification.
- **Benchmark target** — Phase 41g comparator: re-encoded frontier-model thinking traces vs. akh-medu symbolic Loop traces on identical prompts. Either akh-medu's symbolic reasoning beats the imported trace (validates architecture), or the imported trace captures something the symbolic primitives don't yet (validates the bridge captures real frontier reasoning) — both informative.

Pattern B is **not** the same as Pattern C (delegate to local Claude subprocess). Local Claude doesn't expose intermediate thinking blocks; OpenRouter's pass-through to extended-thinking endpoints does.

## Scope (~500 LOC total)

1. **HTTP client + thinking-trace parser** at `src/thinking/openrouter.rs` (~250 LOC).
   - Auth via `AKH_OPENROUTER_API_KEY` env; explicit error-mode if absent.
   - Parses provider-specific thinking-block formats (Anthropic-style `thinking_blocks`, DeepSeek-style `reasoning`, etc.) and normalises to internal `ApiThinkingTrace { chunks, final_answer }`.
   - Cost accounting via `usage` block → `voc_credits` using Phase 36 `CostGuard` model-cost map.
2. **Trace re-encoder** at `src/thinking/trace_reencode.rs` (~250 LOC).
   - For each chunk: encode via Candle backend → `NeuralVsaBridge::encode` → HyperVec; map structural shape to a `ThoughtStep` variant.
   - For final answer: encode and emit `ThoughtStep::ApiTraceConclusion` plus a hypothesis with `BeliefInterval`.
   - All emitted `ThoughtStep`s tagged `ProvenanceTag::ApiTrace { provider, model, chunk_index }` so symbolic-derived steps and API-imported steps are distinguishable.
3. **Loop integration** — new scheduler primitive `ApiTraceReencode { provider, model, prompt }`. Emitted when argumentation produced no clear winner / explicit "frontier comparison" goal tag / Phase 28 router elects this backend.
4. **Provenance commitment** — API-imported steps never count toward `verifier_score` convergence alone; convergence requires symbolic verification of the imported claim.

## Acceptance criterion

End-to-end: prompt sent to OpenRouter with thinking-mode flag, response parsed, each thinking chunk encoded into a `ThoughtStep` carrying `ProvenanceTag::ApiTrace`, hypothesis added to `state.hypotheses`. Fidelity gate: re-encoded thinking-block vectors are within configured cosine threshold of the corresponding chunk's hidden-state representation when both encoders use the same source LLM (only meaningful after Phase 26f).

## Summary
Implement Pattern B of the ThinkingLoop to fetch extended reasoning traces from OpenRouter, re-encode them into internal symbolic thought steps using the NeuralVsaBridge, and integrate them into the local hypothesis superposition for validation and benchmarking. 

## Approach
Create an OpenRouter HTTP client within the AI crate (`crates/anima-ai/src/thinking/openrouter.rs`) that includes authentication, thinking-mode flags, and model-specific JSON parsers to normalize Anthropic/DeepSeek reasoning chunks into an internal `ApiThinkingTrace`. Build a trace re-encoder (`crates/anima-ai/src/thinking/trace_reencode.rs`) that iterates through these normalized chunks, feeding them into the existing `NeuralVsaBridge` to emit structural `ThoughtStep` vectors tagged with `ProvenanceTag::ApiTrace`. Integrate this flow into the workflow scheduler by adding the `ApiTraceReencode` primitive, applying privacy delegation checks mapped from `akh.toml`, and tying token usage metrics to the `CostGuard` module.

## Open questions
* Will OpenRouter normalize the response objects for extended thinking blocks across all supported models (Anthropic vs. DeepSeek), or are divergent raw JSON deserializers required?
* If the `NeuralVsaBridge` encounters an encoding failure or fails the cosine similarity fidelity gate for a single structural chunk, should the engine skip that chunk or discard the entire trace?
* If the `AKH_OPENROUTER_API_KEY` is missing but a comparison goal tag is invoked by the scheduler, should the loop gracefully degrade to local symbolic resolution or throw a hard error?

## Complexity
M: 1-3 days. Building the HTTP client, handling distinct provider response structures, wiring the neural re-encoding loop via the Candle backend, and integrating a new loop primitive into the local scheduler is a moderate, well-scoped effort.
