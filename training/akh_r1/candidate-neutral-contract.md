# Candidate-neutral lifecycle preparation

`pack_preparation.prepare_neutral_lifecycle` reuses the common prepared envelope and private host/public writer. It accepts five lifecycle families, rejects unknown goal fields, strips only the two known legacy dispatch fields (`condition`, `phase`) into private host metadata, and binds inputs to source fingerprints. It does not change frozen clients or make them compatible with the new contract.

The candidate goal is identical across matched control assignments. Public tools and budgets also remain identical. Current source versions, requested tasks and participant identities may remain observable when independently warranted; the expected target, later event and control assignment may not. Private-key checks are defense in depth, not proof against answers embedded in free text. Source admission and a boundary audit are still required.

| Family / retained evidence | Neutral inputs | Host intervention / unresolved execution binding |
|---|---|---|
| Command lifecycle | Requested mode/task, actual help and current version, retained skill | Withhold selected help document or retained skill; live help endpoint must enforce unavailable source |
| Ownership native lifecycle | Task, observed holders/options/epoch | Withhold selected rights/intent receipt; live inquiry endpoint must enforce absence |
| Perception lifecycle | Actual OCR observations, image/source identity, declared spatial assistance | Withhold actual observation record; no invented expected OCR text |
| Language lifecycle | Same instruction, observed source version and snapshot | Withhold snapshot or retained record; do not tell client to block |
| Integrated authority lifecycle | Requested task, live help/rights/feasibility observations | Withhold relevant receipt or memory; reference follows the same policy across assignments |

`observation_view` constructs the actual reduced document/receipt/memory view and rejects absent or duplicate withholding targets. Original records remain preserved. It never fabricates stale content: a stale-record condition must select a separately retained, sourced historical record in a later extension. Merely deleting a goal label does not establish this end-to-end control. Currently views are host-prepared; no dispatcher consumes them, so `executor_binding_ready=false` and `legacy_client_compatible=false` are mandatory.

Eight pure controls cover all five family schemas, matched public tasks, actual view differences, preservation, nested private fields, source changes, invalid withholding, and common writer isolation. Legacy preparation tests must continue passing. These controls use synthetic records and do not replay native/OCR/fixture/model episodes.
